# Ядро бота перевозочных документов

Общее описание, установка и запуск — в [README в корне](../README.md). Здесь —
как бот заполняет поля и разговаривает с бухгалтером.

Документы: **поручение экспедитору**, **заявка перевозчику** (XML по форматам ФНС;
у заявки ещё Word-черновик и текст для мессенджера) и **транспортная накладная,
Титул 1** (XML) — сама по себе или на основании выписанной заявки или поручения.

```bash
PYTHONPATH=. python3 -m pytest tests/ -q
PYTHONPATH=. python3 -m etrn_bot.tools.check_registry   # сверка реестра со схемой
PYTHONPATH=. python3 -m etrn_bot.tools.demo --print     # собрать XML и показать
PYTHONPATH=. python3 -m etrn_bot.tools.smoke            # как бот разговаривает
```

## Как бот закрывает поле

Порядок: **человек → документ → справочник → вычисление → умолчание.**
Спрашивает только то, что не смог добыть сам.

```
EXTRACT  распознать из присланных документов
LOOKUP   достать из справочника по ИНН / госномеру / номеру ВУ
DERIVE   вычислить (номер накладной, дата, плановая дата выгрузки)
DEFAULT  подставить политику организации
ASK      спросить человека
DEFER    не наше поле — заполнит перевозчик, получатель или ГИС ЭПД
```

## «Не знаю» — главная кнопка

Есть на каждом вопросе. Что делает бот:

1. **Поле чужое** (стоимость перевозки, фактические времена, УИД) →
   «Это и не ваше поле, его заполнит перевозчик». Пропускает.
2. **Есть справочник** → лезет туда повторно по уже известному ИНН/номеру.
3. **Есть умолчание** → ставит и говорит какое. `аренда` для ТС,
   `без упаковки` для тары.
4. **Поле необязательное** → оставляет пустым.
5. **Поле критичное** (`never_guess`) → **не угадывает**. Объясняет, зачем
   поле нужно и где его взять, и предлагает прислать документ.

Критичные поля: ИНН всех сторон, наименование и масса груза, количество мест,
адреса погрузки и выгрузки, дата подачи ТС, госномер, ФИО водителя и ВУ.
Здесь ошибка стоит дороже, чем лишний вопрос.

## Юзабилити

- **`/start` объясняет, что делать** — инструкции читать не нужно. Дальше три кнопки:
  поручение, заявка или накладная.
- **Видно, сколько осталось.** «Вопрос 2 из 5», а не бесконечная лента.
- **Документ можно прислать вместо ответа.** Бот спросил ФИО водителя — киньте
  фото прав, он прочитает и пойдёт дальше.
- **Рутина не спрашивается по одному.** НДС, условия оплаты, нормы простоя,
  объём кузова — это коммерческая политика, а не свойства рейса. Показываются
  блоком в карточке, правятся кнопкой. Без этого заявка требовала бы девяти
  подтверждений подряд вместо трёх вопросов.
- **Любое поле правится до сборки** — кнопка «Поправить» со списком.
- **Карточка короткая**, полный список реквизитов — по кнопке.
- **Ошибки формулируются по-человечески.** Не «валидация не пройдена»,
  а «файл не прошёл проверку — это моя ошибка, выпишите пока вручную».
- **Из заявки или поручения в накладную одной кнопкой** — общие поля переносятся,
  спрашивается только водитель и машина.

## Адаптивность

- **Свободная форма.** `тонн двадцать` → 20000 кг. `завтра к 8` → 10.09.2026 08:00.
  `A 123 BC 777` (латиница) → `А123ВС777` (кириллица). ИНН проверяется
  по контрольной сумме — опечатка ловится сразу.
- **Ответ пачкой.** `40 мест, паллеты, завтра к 8` раскладывается по полям.
  В пачке участвуют только типизированные поля — свободный текст спрашивается адресно.
- **«Как в прошлый раз».** Тянет повторяющиеся поля из последней накладной
  по этому получателю. При десяти рейсах в день это экономит больше, чем распознавание.
- **«Зачем?»** на каждом вопросе — бот объясняет, а не отмахивается.
- **Низкая уверенность = вопрос.** Порог 0.75. Плохой скан не проходит молча.
- **Умолчание показывается.** Молча подставленное значение — это ошибка,
  которую никто не заметит. Догадка бота помечается ⚠️ и требует подтверждения;
  осознанная политика организации — нет.
- **Каждое поле в карточке идёт с источником**: `заявка №418`, `справочник`,
  `вы сказали`, `по умолчанию`.

## Чего бот не делает

Не подписывает и не отправляет. УКЭП остаётся у человека, результат работы —
готовый к подписи черновик.
