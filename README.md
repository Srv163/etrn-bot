# ЭТрН-бот

**Телеграм-бот для бухгалтерии грузоотправителя: из пачки сканов и переписки
собирает электронные перевозочные документы по форматам ФНС — поручение
экспедитору, заявку перевозчику и транспортную накладную (ЭТрН).**

*Telegram bot that turns a pile of scans into Russian electronic freight documents
(e-waybill, carrier order, forwarding instruction) in the official FNS XML formats.*

---

## Зачем это нужно

С 1 сентября 2026 года транспортная накладная, заказ или заявка перевозчику и
поручение экспедитору в России оформляются **только в электронном виде**, в
форматах ФНС (закон № 140-ФЗ; бумага — лишь в исключениях из перечней Минтранса).

Каждый такой документ — это XML с десятками обязательных реквизитов. Только в
титуле грузоотправителя ЭТрН схема требует 82 обязательных элемента: телефоны
всех сторон, коды тары, метод определения массы, фактическое время прибытия
машины и так далее. При десяти рейсах в день бухгалтер тратит часы на то, чтобы
перебить в систему ЭДО данные, которые уже есть в сканах, заявках и переписке.

Бот делает это за бухгалтера:

1. Бухгалтер присылает всё, что есть по рейсу: фото прав и СТС, PDF заявки,
   вордовскую карточку контрагента, скриншот переписки.
2. Бот распознаёт документы, достраивает недостающее из справочника и по правилам
   и **спрашивает только то, чего не смог узнать сам**.
3. Показывает карточку, где у каждого значения указан источник.
4. Отдаёт XML-файл, проверенный по схеме ФНС. Бухгалтер загружает его в свою
   систему ЭДО (Saby/СБИС и т. п.), подписывает и отправляет.

## Какие документы собирает

| Документ | Формат ФНС | Когда нужен |
|---|---|---|
| **Поручение экспедитору** (титул клиента) | приказ ЕД-1-26/277@, КНД 1110486 | работаете через экспедитора |
| **Заявка перевозчику** (заказ/заявка, титул грузоотправителя) | приказ ЕД-7-26/108@, КНД 1110361 | заказываете машину у перевозчика напрямую |
| **Транспортная накладная ЭТрН**, титул 1 | приказ ЕД-7-26/1065@, КНД 1110339 | на каждый рейс |

Обычный порядок такой: сначала поручение или заявка, потом накладная **на их
основании**. Бот хранит выписанные документы (60 дней). Когда перевозчик назовёт
водителя и машину, бухгалтер выбирает документ из списка: маршрут, груз и стороны
переносятся, остаётся прислать права и СТС. Если нужна только накладная, бот
соберёт её с нуля.

Для заявки бот дополнительно делает черновик в Word и короткий текст для
мессенджера. Юридической силы у них нет, это просто удобно.

## Как выглядит работа

```
/start → «Накладная ЭТрН» → выбрать организацию
      → «На основании какого документа?» → Заявка №00042 от 09.09.2026 · Химки → Москва
      → «Перенёс маршрут, груз и стороны. Пришлите фото прав и СТС»
      → [фото прав] [СТС тягача] [СТС прицепа] → «Готово, разбирай»
      → «Понял как: водитель Петров Иван Сергеевич, ВУ 9912 345678,
         тягач А123ВС777, прицеп … Верно?»  [Да] [Поправить]
      → «Вопрос 1 из …: фактическое время прибытия под погрузку?» → «сегодня 7:50»
      → карточка → [✅ Всё верно — собрать XML] → ON_TRNACLGROT_…xml
```

Бот понимает свободную форму ответов:

| Бухгалтер пишет | Бот понимает |
|---|---|
| `тонн двадцать` | 20 000 кг |
| `завтра к 8` | 12.09.2026 08:00 |
| `A 123 BC 777` (латиницей) | А123ВС777 |
| `40 мест, паллеты, 10.09 07:50` | три поля одним сообщением |
| `1234567890` в поле ИНН | «контрольная сумма не сходится» — опечатка ловится сразу |
| `Петров И.С.` | «нужно имя полностью, не инициалы» |

На каждом вопросе есть кнопки «Не знаю» и «Зачем?». Если поле заполнит
перевозчик, бот пропустит его. Если значение есть в справочнике, возьмёт оттуда.
Если поле критичное, бот честно скажет, что угадывать не будет, и объяснит, где
взять значение.

## Чему можно доверять

Правила ниже заложены в архитектуру, а не оставлены на усмотрение:

- **Бот не подписывает и не отправляет.** Электронная подпись (УКЭП) остаётся у
  человека. Результат работы бота — готовый к подписи черновик.
- **XML собирает шаблон, а не нейросеть.** Распознавание только достаёт значения
  из сканов. Разметку по схеме строит код.
- **Файл без проверки по схеме ФНС не отдаётся.** Если на сервере нечем проверить
  файл, бот так и скажет и не отдаст непроверенный.
- **Критичные поля не угадываются.** ИНН сторон, наименование и масса груза,
  количество мест, адреса, госномер, ФИО водителя, номер ВУ заполняет только
  документ или человек: ни умолчанием, ни «самым вероятным значением».
- **У каждого значения есть источник**: «заявка №418», «справочник»,
  «вы сказали», «по умолчанию». Сомнительное (уверенность ниже 0,75) бот
  переспрашивает.
- **Сканы не хранятся.** Фото прав и паспортов удаляются сразу после
  распознавания и не попадают ни на диск, ни в логи.
- **Бот запоминает.** Договор с перевозчиком, договор экспедиции, габариты груза,
  реквизиты склада: всё, что бот один раз спросил, на следующем рейсе он уже знает.
  Коммерческие условия (НДС, оплата, простой) не спрашиваются по одному, а
  показываются блоком и правятся кнопкой.

## Состояние проекта

Бот написан и покрыт тестами, но **в Телеграме с живыми бухгалтерами ещё не работал**.

| Что | Статус |
|---|---|
| Реестр реквизитов сверен со схемами ФНС | ЭТрН — 82 обязательных узла, заявка — 58, поручение — 60; непокрытых нет (`check_registry`) |
| XML всех трёх документов проходит проверку по XSD | да, в тестах |
| Полный сценарий бота (накладная, заявка, поручение, накладная на основании) | проходит в тестах на заглушках Телеграма; 246 тестов |
| Распознавание печатных документов (tesseract) | работает: 23 поля из печатной заявки за 0,4 с |
| Распознавание прав, СТС, паспорта через Yandex Vision | подключено, на реальных документах не проверено |
| Работа в Телеграме вживую | **не проверено** |
| Загрузка файлов в Saby/СБИС | **не проверено**: вопросы поддержке — в [`docs/запрос_в_Saby.md`](docs/запрос_в_Saby.md) |
| Контрольные правила ФНС (Schematron) сверх схемы | не проверяются, это делает оператор ЭДО |

Имена файлов обмена содержат идентификаторы участников ЭДО, которые присваивает
оператор. Бот спрашивает их один раз для каждого контрагента и запоминает.

## Установка и запуск

Нужны Python 3.12+ и программа проверки XML `xmllint`. Tesseract и Redis
желательны, но необязательны.

```bash
# Debian / Ubuntu
sudo apt install libxml2-utils tesseract-ocr tesseract-ocr-rus poppler-utils redis-server
# macOS (xmllint уже есть в системе)
brew install tesseract tesseract-lang poppler redis
```

```bash
git clone https://github.com/Srv163/etrn-bot.git
cd etrn-bot
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # вписать BOT_TOKEN от @BotFather
set -a; . ./.env; set +a    # бот читает настройки из переменных окружения
python -m etrn_bot.bot
```

Все настройки описаны с пояснениями в [`.env.example`](.env.example):
токен бота, Redis, распознавание (Yandex Vision или локальный tesseract).
Без Redis бот работает, но после перезапуска забывает незаконченные документы.

В боте: `/orgs` — завести свои организации (их может быть несколько),
`/new` — новый документ.

### Проверить без Телеграма

```bash
PYTHONPATH=. python3 -m pytest tests/ -q                              # все тесты
PYTHONPATH=. python3 -m etrn_bot.tools.check_registry                  # сверка реестра со схемой ЭТрН
PYTHONPATH=. python3 -m etrn_bot.tools.check_registry --doc zayavka    # … заявки
PYTHONPATH=. python3 -m etrn_bot.tools.check_registry --doc poruchenie # … поручения
PYTHONPATH=. python3 -m etrn_bot.tools.demo --print                    # собрать демо-накладную и показать XML
PYTHONPATH=. python3 -m etrn_bot.tools.smoke                           # как бот разговаривает
```

## Как устроено

```
сканы, PDF, Word ─► распознавание ─► разбор и проверка ─► движок заполнения ─► шаблон XML ─► проверка по XSD ─► файл
                    (Yandex Vision /    (ИНН по контр.     (справочник, правила,    (Jinja2)       (xmllint)
                     tesseract)          сумме, госномер…)   вопросы человеку)
```

Всё держится на **реестре реквизитов** ([`etrn_bot/fields.py`](etrn_bot/fields.py)),
единственном источнике правды. Для каждого из 124 полей там записано:

- где оно лежит в схеме каждого документа;
- обязательно ли оно;
- как его добыть и можно ли его угадывать;
- как о нём спросить человека и зачем оно нужно.

Из реестра строятся диалог, карточка, запрос к распознаванию и сверка со схемой.
Правило простое: добавить реквизит в шаблон в обход реестра нельзя.

Порядок заполнения поля: **документ → справочник → вычисление → умолчание →
вопрос человеку.** Поле, которое заполняет другая сторона (перевозчик,
грузополучатель), бот не трогает.

| Путь | Что там |
|---|---|
| `etrn_bot/fields.py` | реестр реквизитов всех трёх документов |
| `etrn_bot/resolve.py` | движок заполнения, справочник, диалог, «не знаю» |
| `etrn_bot/parse.py` | разбор свободной формы: массы, даты, госномера, ИНН, ФИО, адреса |
| `etrn_bot/xml_build.py`, `zakaz_build.py`, `poruch_build.py` | сборка и проверка XML накладной, заявки, поручения |
| `templates/` | шаблоны XML по порядку элементов схем |
| `etrn_bot/yandex_ocr.py`, `ocr.py`, `textscan.py` | распознавание: Yandex Vision, tesseract, разбор текста по подписям |
| `etrn_bot/bot.py` | телеграм-бот на aiogram 3 |
| `etrn_bot/store.py`, `orgs.py` | сессии, счётчик номеров, выписанные документы, профили организаций |
| `schema/` | XSD-схемы ФНС |
| `docs/` | описания форматов ФНС, карты схем, разбор распознавания, запрос в Saby |
| `tests/` | тесты; все данные в них вымышленные |

Файлы `CLAUDE.md` и `STATE_ETRN.md` — рабочие заметки разработки: правила для
ИИ-агента, который пишет код, и журнал решений с замерами. Их полезно читать,
если хотите понять, почему сделано именно так.

## Нормативная база

| Документ | Реквизиты |
|---|---|
| Электронная транспортная накладная | приказ ФНС № ЕД-7-26/1065@ (формат 5.01, часть 973); схема `ON_TRNACLGROT_1_973_01_05_01_02.xsd` |
| Электронный заказ и заявка | приказ ФНС № ЕД-7-26/108@; схема `ON_ZAKZVGO_1_969_01_05_01_01.xsd` |
| Поручение экспедитору | приказ ФНС № ЕД-1-26/277@; схема `ON_POREXPKLT_1_958_05_05_01_01.xsd` |
| Обязательность электронных документов с 01.09.2026 | Федеральный закон № 140-ФЗ; Устав автомобильного транспорта, ст. 8; закон о транспортно-экспедиционной деятельности № 87-ФЗ, ст. 2 |

Схемы взяты с сайта ФНС и лежат в [`schema/`](schema/). Перед работой в
продакшене сверьте их с актуальными версиями на [nalog.gov.ru](https://www.nalog.gov.ru):
ФНС периодически выпускает новые редакции форматов.

## Обратная связь

Бот писался под задачу одной бухгалтерии, но формат у всех грузоотправителей
общий. Если пробуете у себя — пишите в [Issues](https://github.com/Srv163/etrn-bot/issues):
что не распознаётся, какого реквизита не хватает, как ваш оператор ЭДО принимает
файлы. Особенно полезен опыт загрузки в Saby, Контур, Диадок и другие системы.
